The Dive

Learning AI — Claude Code, Codex, running models on your own machine, keeping it all safe, and whatever turns up next. Starting in ankle-deep water and ending somewhere with no sunlight.

Everything here is free to read or watch. Every card links straight to the people who actually made the thing. The deeper you scroll, the harder it gets — that's the whole idea. You do not have to reach the bottom.

The Tide Pool

0–10 m · no experience needed

You can stand up here. Nothing in this section assumes you've written code before — a couple of these are genuinely fun even if you never plan to.

🌟

3Blue1Brown — Neural Networks

A short animated series explaining what a neural network actually does to a number.

Start here: most explanations either hand-wave or drown you in calculus. Grant Sanderson draws it. If you've had algebra, you can follow it, and you'll never unsee it afterwards.

3blue1brown.comfreevideo
 🎺

StatQuest

Josh Starmer explains statistics and machine learning one idea at a time, with terrible jingles.

The friendliest maths teaching I have found anywhere. He assumes nothing and repeats himself on purpose, and the songs make things stick whether you want them to or not. Look up whichever concept just confused you.

youtube.com/@statquestfreevideo
 🔥

Fireship

New tools and languages explained in about a hundred seconds each.

Good for keeping up: this corner of the field changes every few months and hour-long tutorials cannot keep pace. These are fast, funny, and just deep enough to tell you whether something is worth your afternoon.

youtube.com/@Fireshipfreevideo
 🦀

Claude Code — the docs

Anthropic's coding agent that lives in your terminal and edits files in a real project.

Chat windows give you code to copy. This one opens your files, runs your tests, and gets told off when they fail. Read "Overview" then "Common workflows" and skip the rest until you need it.

code.claude.comfreetool
 🐡

Codex CLI

OpenAI's terminal coding agent. Same shape as Claude Code, different brain.

They disagree. Genuinely — and the disagreements are usually where I learn something. A second opinion costs one command.

github.com/openai/codexopen sourcetool
 🦎

OpenCode

A free, open-source terminal coding agent you point at whichever model you like.

Why it's here: Claude Code and Codex both cost money. This one doesn't, and it does the same job well enough to learn on. If you're 15 with no credit card, start here — nothing further down the page changes.

github.com/sst/opencodeopen sourcetool
 ✨

Gemini CLI

Google's terminal agent. Open source, with a generous free tier.

Free requests you don't have to ration. Give it the boring work — renaming things, writing tests — and save your paid quota for the problems that are actually hard.

github.com/google-geminiopen sourcefree
 🎓

Anthropic Academy

Free official courses on Claude, prompting, and building with the API.

It's written by the people who built the model, so it's current. Third-party tutorials about AI tools go stale in about four months.

anthropic.com/learnfreecourse
 🐙

Kaggle Learn

Short hands-on courses — Python, pandas, intro ML — run in your browser, no install.

Each lesson is about an hour and ends with you having done the thing rather than read about it. "Intro to Machine Learning" is the shortest honest route I know from zero to a working model.

kaggle.com/learnfreehands-on
 🪸

Hugging Face Learn

Free course tracks on LLMs, agents, diffusion models and audio.

You're learning on the same library the field actually uses, so nothing you practise is throwaway. Start the LLM course, ignore the rest until it's relevant.

huggingface.co/learnfreehands-on

Midwater

10–200 m · you can code a little

Light's getting thin. This is where you stop asking an AI for snippets and start building it a workshop — skills it can reuse, tools it can reach, and rules that stop it wrecking your code.

🐬

Agent Skills

A folder with instructions in it. Claude loads it when the task matches.

Instead of re-explaining your workflow every session, you write it down once. It's the difference between giving directions and drawing a map.

code.claude.com/docsdocsbuild
 📺

Computerphile

Short whiteboard interviews with researchers — tokenisation, transformers, how the pieces fit.

Ten minutes, a sheet of paper, and someone who actually knows the subject. No production gloss and no hype. When a word on this page stops making sense, there is usually a Computerphile video that fixes it.

youtube.com/@Computerphilefreevideo
 🦐

anthropics/skills

Anthropic's own open-source skills — real ones, in use.

Read these before writing your own: your first instinct will be to write a 400-line skill. These are mostly short and specific, and that's the actual lesson.

github.com/anthropics/skillsopen sourceexamples
 🐙

MCP — Model Context Protocol

A standard way to plug an agent into real tools and data: databases, APIs, your files.

A model that can't reach anything can only guess. MCP is how it gets hands. It's also an open standard, so what you learn transfers across tools.

code.claude.com/docsdocsbuild
 🦈

Codex plugin for Claude Code

Official OpenAI plugin. Adds /codex:review and an adversarial review that argues with your design.

A model reviewing its own work is a bad judge — it likes what it wrote. A different model has no such loyalty. The adversarial mode attacks your approach, not just your syntax.

github.com/openai/codex-plugin-ccopen sourcetool
 🧹

Karpathy's four rules

A tiny rules file: four rules answering the three ways LLMs habitually ruin code.

Models assume silently, overbuild, and edit things you didn't ask about. Naming those three failures in writing is most of the fix. One file, five minutes.

github.com/forrestchangopen sourceconfig
 ⚓

12-Factor Agents

Twelve principles for agents that survive contact with reality.

Read it early: it's the "here's what breaks in production" document, written before you've had it break. Own your prompts, own your control flow, keep the agent small. Dry in places. Worth it.

github.com/humanlayeropen sourceguide
 📕

Claude Cookbooks

Runnable notebooks: tool use, retrieval, vision, evaluation, sub-agents.

You can run a cell, break it, and see what the model does. Fastest way to build a real feel for how these systems behave.

github.com/anthropicsopen sourcenotebooks
 📗

OpenAI Cookbook

The same idea from the other side — hundreds of worked examples.

The two ecosystems solve identical problems with different vocabulary. Reading both is how you learn which ideas are real and which are just branding.

github.com/openaiopen sourcenotebooks
 🐝

Cline

An open-source agent that lives inside VS Code instead of the terminal.

Terminal agents ask you to trust a wall of text. Cline shows every edit as a diff you approve one at a time.

github.com/cline/clineopen sourcetool
 🧰

Claude Agent SDK

The library for building your own agent instead of using someone else's.

When you outgrow the ready-made ones: this is how you build an agent shaped like your actual problem. Same machinery Claude Code runs on, exposed.

github.com/anthropicsopen sourcetool
 📏

Terminal-Bench

The benchmark these coding agents are scored on, with a public leaderboard.

Every tool claims it is the best. This is where you check. Read how the tasks are built and you will start noticing which claims are measured and which are vibes.

tbench.aifreebenchmark

The Trench

200 m+ · bring a light

No sunlight. This is where you stop using models and start building them — backpropagation by hand, an LLM from an empty file, and one paper that keeps turning up in everything else. Slow going on purpose. Nobody finishes this section in a weekend.

🦴

Neural Networks: Zero to Hero

Andrej Karpathy builds backpropagation, then a language model, from an empty file. On video.

No library does the thinking for you. By the end you've written the maths yourself and the word "gradient" stops being scary. This is the one that helped me most.

github.com/karpathyvideocode along
 📘

Build an LLM from Scratch

Sebastian Raschka's book repo: tokenizer, attention, pretraining, fine-tuning — step by step in PyTorch.

He shows you the idea; this shows you the engineering. Chapter 3 (attention) is the one everyone screenshots, and deservedly.

github.com/rasbtcodefree repo
 🐟

fast.ai — Practical Deep Learning

Jeremy Howard's course. You train a working model in lesson one, theory arrives later.

The backwards order helps: most courses teach maths for six weeks before anything works, and most people quit in week three. This one hands you a result first. If Karpathy's approach felt too dry, start here instead.

course.fast.aifreecourse
 📄

DeepSeekMath — the GRPO paper

Introduces Group Relative Policy Optimization, the RL method behind a lot of recent reasoning work.

If you only read one RL-for-reasoning paper, GRPO is the idea that keeps reappearing. Read the method section, skip the benchmark tables on a first pass.

arxiv.org/abs/2402.03300paperopen access
 📰

Two Minute Papers

Short summaries of brand-new AI research papers, delivered with real delight.

If the papers are too much: this is the gentlest way to keep up with what is being published. His enthusiasm is contagious, and every video names the paper, so you can go and read it properly when one grabs you.

youtube.com/@TwoMinutePapersfreevideo
🚢

The Wreck

learning from other people's mistakes

Divers study wrecks to learn what sinks ships. Same logic here. An AI agent that can read your files, run commands and reach the internet is useful for exactly the reason it is dangerous — and the failures are well documented, so you can learn them without being the example.

⚠️

OWASP Top 10 for LLM Apps

The industry list of what actually goes wrong, maintained by the OWASP GenAI project.

Prompt injection still tops it, and “excessive agency” has climbed sharply now that agents are doing real damage in production. Ten named failures is more use than a vague sense that this might be risky.

genai.owasp.orgfreereference
 🎣

Prompt injection, explained

Simon Willison's running archive on the attack — he coined the term and has tracked it since.

He keeps posting real examples as they appear, including the ones nobody has fixed. His central point is uncomfortable and worth absorbing early: there is still no reliable fix, only reduced blast radius.

simonwillison.netfreereading
 🔐

Permissions and sandboxing

How to control what an agent is allowed to touch — allowlists, deny rules, sandbox mode, approval prompts.

The fix for “the agent did something I didn't expect” is almost never a better prompt. It is narrower permissions. Read this before you turn off approval prompts, not after.

code.claude.com/docsfreeconfig
 🔌

MCP security best practices

The security guidance for connecting agents to outside tools and data over MCP.

Bigger than it sounds: the moment you plug an agent into your email, database or calendar, every document it reads becomes a possible instruction. This is the page that explains why, and what to do about it.

modelcontextprotocol.iofreespec
 🧪

Promptfoo red teaming

An open-source tool that attacks your own AI app and reports what got through.

You can read about prompt injection for a week and still not know whether your thing is vulnerable. This runs the attacks and tells you. It maps its checks to the OWASP list above, so the two fit together.

promptfoo.devopen sourcetool
 🦞

Codex — official developer docs

Configuration, sandboxing, automation and the agent's approval model.

Sandbox and approval settings decide what an agent is allowed to do to your machine. That is worth reading from the source rather than from someone's blog post.

developers.openai.comdocsreference

Build Your Own Submarine

your hardware · your data · no bill

Everything above runs on somebody else's computer. This section doesn't. A model on your own Mac mini, iPad or phone costs nothing per question, works on a plane, and keeps your data on your device.

Rough hardware guide (2026): RAM is the limit, not the chip. A base Mac mini M4 comfortably runs 7–8B models — genuinely useful for writing, code and summarising. A Mac mini M4 Pro with 48GB reaches 70B models at 4-bit, which is where local starts to feel close to the paid services. iPhone and iPad run smaller on-device models through Apple's own framework. For local models, RAM matters more than speed.
🐋

Ollama

One command to download and run a local model. Now uses Apple's MLX backend on Apple Silicon.

Start here: from nothing to talking with a local model in about five minutes, and it manages the downloads for you. If you only ever use one thing from this section, use this one.

ollama.comfreetool
 🎛️

LM Studio

A desktop app for finding, downloading and chatting with local models. No terminal at all.

It shows you which models will actually fit in your RAM before you download 40GB. If the command line is a barrier — or you're setting this up for someone younger — start here instead.

lmstudio.aifreeapp
 ⚡

MLX

Apple's own array framework, built for Apple Silicon's unified memory.

On a Mac the CPU and GPU share one pool of memory, so a 32GB Mac mini can hold models that would need a far pricier graphics card otherwise. MLX is the library written to exploit exactly that.

github.com/ml-exploreopen sourcetool
 📦

mlx-lm

Run and fine-tune language models with MLX — including LoRA fine-tuning on your own Mac.

The one I got most excited about: fine-tuning used to mean renting cloud GPUs. With a decent Mac mini you can now train a small model on your own notes, your own writing, your own data, and never upload any of it.

github.com/ml-exploreopen sourcetool
 🍎

Apple Foundation Models

The on-device model built into recent iPhone, iPad and Mac systems, callable from your own app in Swift.

Nothing to download, no API key, no running costs, and it works in airplane mode. It is a small model, so don't ask it to write your dissertation — but for an app that summarises, sorts or rewrites, it's free and instant.

developer.apple.comfreeframework
 📱

MLX Swift examples

Working sample apps that run language and image models on iPhone and iPad.

Reading about on-device inference is abstract until a model is generating text on your own phone with the wifi off. These build and run — start by changing the model, then change the app.

github.com/ml-exploreopen sourcetool
 🔧

llama.cpp

The C++ engine that a large share of local AI tools quietly run on underneath.

Worth opening eventually: Ollama and LM Studio are friendly wrappers. When you want to understand quantisation — why a model shrinks to a quarter of its size and stays useful — this is where that actually happens.

github.com/ggml-orgopen sourcetool
